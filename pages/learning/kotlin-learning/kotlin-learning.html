Introduction to Kotlin

Kotlin is a modern, statically typed programming language that runs on the Java Virtual Machine (JVM). Developed by JetBrains and officially launched in 2016, it was designed to be fully interoperable with Java while being more concise, expressive, and safe.

In 2019, Google announced Kotlin as the preferred language for Android development, and it has since grown into a versatile language used for backend services (Ktor, Spring Boot), multiplatform mobile apps (KMP), and even web development (Kotlin/JS).

Why Learn Kotlin?

  • Concise & Expressive: Eliminates boilerplate — Java's getters/setters, constructors, and equals/hashCode collapse into a single line.
  • Null Safety Built-In: The type system distinguishes between nullable and non-nullable types, eliminating null pointer exceptions at compile time.
  • Full Java Interop: Use any Java library directly from Kotlin and vice versa — no adapter layer needed.
  • Coroutines: First-class structured concurrency for async, non-blocking code that's easy to read and reason about.
  • Modern Ecosystem: Backed by JetBrains, adopted by Google, and powering major apps like Trello, Evernote, and Pinterest.

    println("Hello, Kotlin!")
    println("Concise. Safe. Modern.")
}

Variables & Data Types

Kotlin offers two keywords for declaring variables: val (immutable / read-only) and var (mutable). The language features strong type inference, so you rarely need to declare types explicitly.

val vs var

  • val — A read-only reference. Once assigned, it cannot be reassigned (similar to final in Java). Prefer val by default.
  • var — A mutable reference. Its value can be changed after assignment.
Kotlin 
// Immutable (read-only) reference
val name: String = "Alice"
val age = 30           // Type inferred as Int

// Mutable reference
var score = 95
score = 100            // OK: var can be reassigned

// Basic types
val greeting: String = "Hello"
val year: Int = 2026
val pi: Double = 3.14159
val isActive: Boolean = true
val initial: Char = 'K'
val bigNumber: Long = 9_000_000_000L
val temperature: Float = 23.5F

// String templates
val message = "User: $name, Score: ${score + 5}"
println(message)
Output
User: Alice, Score: 105

Use val by default and only switch to var when you have a compelling reason to mutate. This makes your code easier to reason about and thread-safe by design.

Control Flow

Kotlin provides familiar control flow constructs with a modern twist. The if expression returns a value, and when replaces Java's switch with far more expressive power.

Kotlin 
fun main() {
    val score = 85

    // if as an expression (returns a value)
    val grade = if (score >= 90) {
        "A"
    } else if (score >= 80) {
        "B"
    } else {
        "C"
    }
    println("Grade: $grade")

    // when expression (replaces switch)
    val status = when (grade) {
        "A" -> "Excellent"
        "B" -> "Good"
        "C" -> "Average"
        else -> "Unknown"
    }
    println("Status: $status")

    // for loop with ranges
    for (i in 1..3) {
        print("$i ")
    }

    // while loop
    var x = 3
    while (x > 0) {
        print("$x ")
        x--
    }
}
Output
Grade: B
Status: Good
1 2 3
3 2 1

Ranges

  • 1..5 — closed range (includes 1, 2, 3, 4, 5)
  • 1..<5 — half-open range (includes 1, 2, 3, 4)
  • 5 downTo 1 — reversed range
  • 1..10 step 2 — range with step (1, 3, 5, 7, 9)
Practice: Control Flow

Correct Answer: B

Both if and when can be used as expressions in Kotlin, meaning they return values that can be assigned to variables. This makes code more concise and functional.

Functions & Lambdas

Functions are declared with the fun keyword. Kotlin supports default arguments, named parameters, single-expression functions, and first-class lambda expressions for functional programming.

Kotlin 
// Standard function with default argument
fun greet(name: String = "Guest"): String {
    return "Hello, $name!"
}

// Single-expression function (concise)
fun double(x: Int): Int = x * 2

// Named arguments
fun createUser(name: String, age: Int, role: String = "user") {
    println("$name is $age years old, role: $role")
}

// Lambda expression
val sum: (Int, Int) -> Int = { a, b -> a + b }

// Higher-order function
fun operateOnNumbers(a: Int, b: Int, operation: (Int, Int) -> Int): Int {
    return operation(a, b)
}

fun main() {
    println(greet("Alice"))
    println(double(21))
    createUser(age = 25, name = "Bob")
    println(sum(3, 4))

    val result = operateOnNumbers(10, 5) { x, y -> x - y }
    println("Subtraction: $result")
}
Output
Hello, Alice!
42
Bob is 25 years old, role: user
7
Subtraction: 5

Trailing lambda syntax: When the last parameter of a function is a lambda, you can move it outside the parentheses. This enables clean DSL-like APIs.

Null Safety

Kotlin's type system eliminates null pointer exceptions (NullPointerException) at compile time. The distinction between nullable and non-nullable types is baked into the language itself.

Nullable vs Non-Nullable Types

  • Non-nullable: String name = "Alice" — can never hold null. Safe to access without checks.
  • Nullable: String? name = null — declared with ? suffix. Must be handled safely before use.
Kotlin 
var nonNullable: String = "Hello"
// nonNullable = null // Compile error!

var nullable: String? = "World"
nullable = null  // OK: nullable type

// 1. Safe call operator (?.)
val length: Int? = nullable?.length

// 2. Elvis operator (?:)
val result = nullable ?: "Default value"

// 3. Safe cast (as?)
val obj: Any = "Kotlin"
val str: String? = obj as? String

// 4. let + safe call pattern
nullable?.let {
    println("Value is not null: $it")
}

// Practical example
fun getUserName(id: Int): String? {
    return if (id == 1) "Alice" else null
}

val name = getUserName(5) ?: "Unknown"
println(name)  // Unknown

Avoid the !! operator in production code. It re-introduces the risk of NullPointerException. Prefer ?.let, ?: (Elvis), and safe casts for idiomatic Kotlin.

Practice: Null Safety

What does the Elvis operator (?:) do in Kotlin?

  1. Throws an exception if the left side is null
  2. Returns the left side if non-null, otherwise returns the right side
  3. Converts a nullable type to a non-nullable type
  4. Performs a null-safe method call

Correct Answer: B

The Elvis operator ?: returns the left-hand expression if it's not null; otherwise it evaluates and returns the right-hand expression. It's named after Elvis Presley's hair — the ?: resembles his pompadour hairstyle.

Extension Functions & Properties

Extension functions allow you to add new functionality to existing classes without inheriting from them or using design patterns like Decorator. This is one of Kotlin's most powerful features for writing clean, expressive code.

Kotlin 
// Extension function on String
fun String.isEmail(): Boolean {
    return this.contains("@") && this.contains(".")
}

// Extension property on String
val String.isLong: Boolean
    get() = this.length > 10

// Extension on a generic List
fun List<T>.secondOrNull(): T? {
    return if (this.size >= 2) this[1] else null
}

fun main() {
    val email = "alice@example.com"
    println(email.isEmail())     // true

    println("Hello World".isLong) // true

    val list = listOf(1, 2, 3)
    println(list.secondOrNull())  // 2

    fun Int.triple(): Int = this * 3
    println(7.triple()) // 21
}
Output
true
false
true
2
null
21

Object-Oriented Kotlin

Kotlin is fully object-oriented with concise syntax for classes, inheritance, data classes, and singletons. It also introduces data classes and sealed classes that reduce boilerplate significantly compared to Java.

Kotlin 
// Data class
data class User(
    val id: Int,
    val name: String,
    val email: String? = null
)

// Class with constructor
class Counter(private var count: Int = 0) {
    fun increment() { count++ }
    fun value(): Int = count
}

// Inheritance
open class Animal(val name: String) {
    open fun speak() = println("$name makes a sound")
}

class Dog(name: String) : Animal(name) {
    override fun speak() = println("$name barks!")
}

// Singleton
object AppConfig {
    const val VERSION = "1.0.0"
}

// Sealed class
sealed class Result {
    data class Success(val data: String) : Result()
    data class Error(val message: String) : Result()
    object Loading : Result()
}
Output
User(id=1, name=Alice, email=alice@example.com)
Buddy barks!
[App] App started

Data classes are one of Kotlin's most loved features — a single line gives you toString(), equals(), hashCode(), copy(), and componentN() (destructuring declaration) functions.

Collections & Sequences

Kotlin's standard library offers rich collection types with a powerful functional API. Distinguish between eager (List, Set, Map) and lazy (Sequence) evaluation to write efficient data pipelines.

Collection Types

  • List<T> — Ordered collection with indexed access (mutable: mutableListOf)
  • Set<T> — Unique elements with no defined order (mutable: mutableSetOf)
  • Map<K, V> — Key-value pairs (mutable: mutableMapOf)
  • Sequence<T> — Lazy evaluation for large data pipelines — elements are computed on demand
Kotlin 
fun main() {
    val fruits = listOf("Apple", "Banana", "Cherry")
    val mutableFruits = mutableListOf("Apple", "Banana")
    mutableFruits.add("Cherry")

    // Functional operations
    val numbers = listOf(1, 2, 3, 4, 5, 6)

    val evenSquares = numbers
        .filter { it % 2 == 0 }
        .map { it * it }
    println(evenSquares)  // [4, 16, 36]

    // Sequence: lazy evaluation
    val largeSequence = (1..1_000_000)
        .asSequence()
        .filter { it % 2 == 0 }
        .map { it * 2 }
        .take(5)
        .toList()
    println(largeSequence)  // [4, 8, 12, 16, 20]
}
Output
[4, 16, 36]
[3, 4]
[1, 2, 3, 4, 5, 6]
User 1: Alice
User 2: Bob
User 3: Charlie
[4, 8, 12, 16, 20]
Practice: Collections & Sequences

What is the key difference between a List operation chain and a Sequence chain?

  1. Sequences are mutable; Lists are immutable
  2. Sequences evaluate lazily — each element flows through the pipeline one at a time
  3. Lists support filter and map but Sequences do not
  4. Sequences always produce null values

Correct Answer: B

Sequences use lazy evaluation — intermediate operations create a pipeline that processes elements one at a time only when a terminal operation (like toList()) is called. This avoids creating intermediate collections at each step, significantly reducing memory usage for large datasets.

Coroutines & Concurrency

Coroutines are Kotlin's approach to asynchronous programming — lightweight threads that can be suspended and resumed without blocking the underlying thread. They enable writing async code that looks and behaves like sequential code.

Key Concepts

  • Suspend Function: A function marked with suspend that can be paused and resumed later without blocking the current thread.
  • CoroutineScope: Defines the lifecycle of coroutines within it — all coroutines launched in a scope are cancelled when the scope is cancelled.
  • Dispatchers: Control which thread pool the coroutine runs on (Main, IO, Default, Unconfined).
  • Structured Concurrency: Coroutines are hierarchical — a parent coroutine is not completed until all its child coroutines complete.
Kotlin 
// Suspend function
suspend fun fetchUserData(userId: Int): String {
    delay(1000)  // Non-blocking sleep
    return "User data for #$userId"
}

fun main() = runBlocking {
    // Launch concurrent tasks
    val result1 = async { fetchUserData(1) }
    val result2 = async { fetchUserData(2) }

    println(result1.await())
    println(result2.await())

    // Fire-and-forget
    launch {
        repeat(3) { i ->
            delay(200)
            println("Tick $i")
        }
    }

    // IO dispatcher
    launch(Dispatchers.IO) {
        println(fetchUserData(3))
    }

    println("All results received!")
}
Output (approximate)
Starting...
Tick 0
Tick 1
All results received!
User data for #1
User data for #2
Tick 2
User data for #3

runBlocking bridges the synchronous world (main function) with the coroutine world. Use it only at the top level of your application. In production Android code, use lifecycleScope or viewModelScope instead.

Practice: Coroutines

What does the suspend keyword enable a function to do?

  1. Run on a separate thread automatically
  2. Be paused and resumed without blocking the thread
  3. Return multiple values
  4. Access UI components from any thread

Correct Answer: B

A suspend function can be paused at a suspension point (like delay() or await()) and resumed later, all without blocking the underlying thread. This allows efficient concurrency with a fraction of the threads needed for traditional approaches.

Android-Specific Patterns

Kotlin is the preferred language for Android development. Modern Android apps leverage Jetpack libraries with Kotlin-first APIs, ViewModel + StateFlow for state management, Room for local storage, and Jetpack Compose for declarative UI.

Common Android Patterns with Kotlin

  • ViewModel + StateFlow: Expose UI state as a StateFlow from the ViewModel for reactive, lifecycle-aware updates.
  • Room Database: Use Kotlin coroutines and Flow for reactive database queries.
  • Jetpack Compose: Build declarative UIs with composable functions — no XML layouts needed.
  • Dependency Injection: Hilt/Dagger with Kotlin's annotation processing for constructor injection.
Kotlin — Android ViewModel 
// ViewModel with StateFlow
class MainViewModel : ViewModel() {

    private val _uiState = MutableStateFlow(UiState())
    val uiState: StateFlow<UiState> = _uiState.asStateFlow()

    data class UiState(
        val isLoading: Boolean = false,
        val username: String = "",
        val error: String? = null
    )

    fun loadUser(userId: Int) {
        _uiState.update { it.copy(isLoading = true) }

        viewModelScope.launch {
            try {
                val user = repository.getUser(userId)
                _uiState.update {
                    it.copy(isLoading = false, username = user.name)
                }
            } catch (e: Exception) {
                _uiState.update {
                    it.copy(isLoading = false, error = e.message)
                }
            }
        }
    }
}

// Jetpack Compose UI
@Composable
fun UserScreen(viewModel: MainViewModel) {
    val state by viewModel.uiState.collectAsState()

    if (state.isLoading) {
        CircularProgressIndicator()
    } else {
        Text("Hello, ${state.username}!")
    }
}

Room Database with Coroutines

  • DAO methods can be suspend functions for one-shot queries
  • Flow return types for reactive, observable queries that emit whenever the underlying table changes
  • Auto-migration with Schema export for safe database version upgrades
Kotlin — Room + Flow 
// Room Entity
@Entity(tableName = "users")
data class UserEntity(
    @PrimaryKey val id: Int,
    val name: String,
    val email: String?
)

// DAO with coroutines and Flow
@Dao
interface UserDao {
    @Query("SELECT * FROM users WHERE id = :userId")
    fun getUser(userId: Int): Flow<UserEntity?>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertUser(user: UserEntity)

    @Query("DELETE FROM users")
    suspend fun deleteAll()
}

What is the benefit of using StateFlow over LiveData in a ViewModel?
