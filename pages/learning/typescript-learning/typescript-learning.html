01

Types & Type Annotations

TypeScript is a statically typed superset of JavaScript. Every variable, parameter, and return value can declare its type. The compiler catches mismatches before your code ever runs -- catching entire categories of bugs at compile time.

Primitive Types

  • string -- textual data ("hello", 'world')
  • number -- all numeric values (42, 3.14, 0xFF)
  • boolean -- true or false
  • null / undefined -- the absence of a value
  • void -- the return type of a function that returns nothing
  • never -- a value that never occurs (e.g. a function that always throws)
  • any -- opt-out of type checking (use sparingly)
  • unknown -- type-safe counterpart of any (requires narrowing)
TypeScript 
// Type annotations
let username: string = "alice";
let age: number = 30;
let isAdmin: boolean = false;
let nothing: null = null;
let notDefined: undefined = undefined;

// Type inference -- TS deduces the type
let message = "Hello, TypeScript!";
// message = 42; // Error

// Array types
let scores: number[] = [95, 87, 92];
let names: Array<string> = ["Alice", "Bob", "Charlie"];

// Tuples -- fixed-length arrays with typed positions
let pair: [string, number] = ["version", 5.3];

// Union type
let identifier: string | number = "user_001";
identifier = 1001; // OK

Prefer unknown over any. unknown forces you to narrow the type before using it (via typeof, instanceof, or type guards), making your code safer while still flexible.

Interfaces & Type Aliases

Interfaces and type aliases are TypeScript's primary tools for shaping objects. They define contracts that values must satisfy, enabling the compiler to verify structural correctness across your codebase.

Interfaces

  • Define the shape of an object with named properties and their types
  • Optional properties marked with ? -- the property may be absent
  • readonly properties cannot be reassigned after creation
  • Interfaces support extension via extends
  • Can be declaration-merged -- multiple declarations with the same name are merged
TypeScript 
interface Book {
  title: string;
  author: string;
  isbn?: string;
  readonly publishedYear: number;
}

interface EBook extends Book {
  format: "pdf" | "epub" | "mobi";
  fileSizeMb: number;
}

type Library = Record<string, Book>;

Generics -- Reusable Type-Safe Code

Generics allow you to write functions, classes, and interfaces that work with any type while preserving type safety. Instead of using any and losing type information, you capture the type as a parameter -- just like a function captures a value.

Generic Fundamentals

  • Type parameters use angle bracket syntax: <T> (commonly T, K, V)
  • Constraints restrict type parameters with extends: <T extends HasLength>
  • Generic interfaces define reusable contracts: interface Box<T> { value: T }
  • Multiple type parameters: <K, V> for key-value pairs
  • Default types: <T = string>
TypeScript 
// Generic identity function
function identity<T>(arg: T): T {
  return arg;
}

// Generic interface
interface Repository<T> {
  getById(id: string): T;
  getAll(): T[];
  create(item: T): void;
}

// Constrained generic
function logLength<T extends { length: number }>(arg: T): T {
  console.log(arg.length);
  return arg;
}

// Keyof constraint
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

Generics vs any: Using any opts out of type checking entirely -- you lose editor autocompletion, compile-time validation, and refactoring safety. Generics preserve all of that while keeping your code flexible. Always prefer generics over any for reusable logic.

}
04

Enums & Union Types

Enums give meaningful names to sets of related constants. Union types let a value be one of several types. When combined with discriminated unions, they form one of the most powerful patterns in TypeScript -- enabling exhaustive type checking over complex state.

Enums

  • Numeric enums auto-increment from 0 (or a custom start value)
  • String enums have no auto-incrementing -- each member must be initialized
  • Enums create both a type and a runtime value
  • Use const enum to avoid runtime overhead (values are inlined)
TypeScript 
// Numeric enum
enum Direction {
  Up,      // 0
  Down,    // 1
  Left,    // 2
  Right,   // 3
}

// String enum
enum Color {
  Red = "RED",
  Green = "GREEN",
  Blue = "BLUE",
}

// Union type
type Status = "idle" | "loading" | "success" | "error";

// Discriminated union
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; sideLength: number }
  | { kind: "rectangle"; width: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":    return Math.PI * shape.radius ** 2;
    case "square":    return shape.sideLength ** 2;
    case "rectangle": return shape.width * shape.height;
  }
}

Type Narrowing

TypeScript narrows the type of a value based on runtime checks. Common narrowing techniques:

  • typeof guards: typeof x === "string"
  • in operator: "radius" in shape
  • instanceof checks: error instanceof TypeError
  • Discriminated union: checking the kind property narrows the rest

Utility Types -- Transform Types on the Fly

TypeScript ships with a rich set of utility types that transform existing types into new ones. They reduce boilerplate and ensure consistency -- instead of redefining partial or derived types, you compose them from the source of truth.

Common Utility Types

  • Partial<T> -- all properties become optional
  • Required<T> -- all properties become mandatory
  • Readonly<T> -- all properties become readonly
  • Pick<T, K> -- select a subset of properties
  • Omit<T, K> -- exclude a subset of properties
  • Record<K, V> -- construct an object type with keys K and values V
  • Exclude<T, U> -- exclude members from a union
  • NonNullable<T> -- remove null and undefined
  • ReturnType<T> -- extract the return type of a function type
  • Parameters<T> -- extract parameter types as a tuple
TypeScript 
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  createdAt: Date;
}

// Partial -- useful for updates
function updateUser(id: number, changes: Partial<User>): void {}

// Pick & Omit
type UserPreview = Pick<User, "id" | "name">;
type PublicUser = Omit<User, "password">;

// Record
type UserMap = Record<string, User>;

// ReturnType
type FetchResult = ReturnType<typeof fetchUser>;

// NonNullable
type DefinitelyString = NonNullable<string | null | undefined>;
Utility Input Output Use Case
Partial<T>InterfaceAll optionalUpdate payloads
Required<T>InterfaceAll requiredForm validation
Pick<T, K>Type + keysSubsetAPI responses
Omit<T, K>Type + keysExclusionStripping sensitive fields
Record<K, V>Keys + valuesObject mapDictionaries, caches
ReturnType<T>Function typeReturn typeType inference from functions

Utility types use mapped types and conditional types internally. You can build your own by combining these patterns -- e.g., type Nullable<T> = { [K in keyof T]: T[K] | null }.

Real-World TypeScript Patterns

Let's bring everything together with practical patterns you will use daily. These features -- optional chaining, nullish coalescing, type guards, and async typing -- make TypeScript a joy to work with in production applications.

Modern JavaScript Features (TypeScript-Enhanced)

  • Optional chaining (?.) -- safely access deeply nested properties without checking each level
  • Nullish coalescing (??) -- fall back to a default only for null or undefined (unlike || which catches all falsy values)
  • Type predicates -- custom type guards with is return type
  • Async/await with strict typing -- fully typed async functions
TypeScript 
// Nullish coalescing
function getTimeout(config: Config): number {
  return config.api?.timeout ?? 3000;
}

// Type predicate
function isCat(pet: Cat | Dog): pet is Cat {
  return (pet as Cat).meow !== undefined;
}

// Generic API response
interface ApiResponse<T> {
  data: T;
  error?: string;
  status: number;
}

async function fetchJson<T>(url: string): Promise<ApiResponse<T>> {
  try {
    const res = await fetch(url);
    const data = await res.json();
    return { data, status: res.status };
  } catch (err) {
    return { data: null as T, error: String(err), status: 500 };
  }
}

Key Takeaways

  • Optional chaining (?.) prevents the dreaded Cannot read property of undefined at runtime
  • Nullish coalescing (??) is safer than || when 0, "", and false are valid values
  • Type predicates enable custom narrowing logic that the compiler trusts
  • Generic async functions give you reusable, fully typed data fetching

Build a typed user search function:

  1. Define an interface User with id: number, name: string, email: string
  2. Define a type SearchResult<T> as { results: T[]; total: number; hasMore: boolean }
  3. Write an async function searchUsers(query: string): Promise<SearchResult<User>> that uses fetchJson behind the scenes
  4. Use optional chaining to safely access results[0]?.name
TypeScript 
interface User {
  id: number;
  name: string;
  email: string;
}

type SearchResult<T> = {
  results: T[];
  total: number;
  hasMore: boolean;
};

async function searchUsers(query: string): Promise<SearchResult<User>> {
  const response = await fetchJson<User[]>(`/api/users?q=${query}`);
  if (response.error) {
    return { results: [], total: 0, hasMore: false };
  }
  return {
    results: response.data,
    total: response.data.length,
    hasMore: response.data.length > 0,
  };
}

// Safe access with optional chaining
const firstUserName = results?.[0]?.name;
