Why Flutter & Getting Started

Flutter is Google's open-source UI toolkit for building natively compiled apps for mobile, web, and desktop -- all from a single Dart codebase. Instead of writing separate apps for iOS and Android, you write the UI once and Flutter draws every pixel itself, giving you fast, consistent results everywhere.

Why developers choose Flutter

  • One codebase -- ship the same Dart code to iOS, Android, web, and desktop
  • Hot Reload -- change code and see the UI update in under a second
  • Native performance -- Dart compiles ahead-of-time (AOT) to machine code
  • Rich widget catalog -- Material and Cupertino widgets out of the box
  • Great tooling -- Android Studio, VS Code, and an excellent CLI
Terminal 
# Create a new Flutter project
flutter create my_app
cd my_app
flutter pub get
flutter analyze
flutter run

Every Flutter app starts from main(). It calls runApp() with your root widget -- the top of your widget tree. Everything you see on screen is a widget, and widgets are just Dart classes that describe part of the UI.

Dart 
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'My Flutter App',
      home: Scaffold(
        appBar: AppBar(title: const Text('Welcome')),
        body: const Center(
          child: Text('Hello, Flutter!'),
        ),
      ),
    );
  }
}

pubspec.yamlDependencies and assets (like package.json)
test/Widget and unit tests
android/ & ios/Native platform shells

Prefer const constructors. When a widget can't change, mark it const. It lets Flutter skip rebuilding it entirely -- a simple, automatic performance win.

Widgets -- The Building Blocks

In Flutter, everything is a widget. Text, padding, rows, even the app itself -- all widgets. You build a UI by composing small widgets inside bigger ones, forming a widget tree. The parent passes data down to its children, and Flutter turns the whole tree into pixels.

Widget fundamentals

  • StatelessWidget -- describes UI that never changes on its own
  • StatefulWidget -- holds mutable state and can rebuild itself
  • Widgets are immutable descriptions -- config in, pixels out
  • Common building blocks: Text, Icon, Image, Container, Row, Column
Dart 
import 'package:flutter/material.dart';

class GreetingCard extends StatelessWidget {
  const GreetingCard({super.key});

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.all(16.0),
      child: Column(
        children: [
          const Icon(Icons.waving_hand, size: 48, color: Colors.blueGrey),
          const Text('Hello!', style: TextStyle(fontSize: 24)),
          Text(
            'Welcome to Flutter',
            style: TextStyle(color: Colors.grey[600]),
          ),
        ],
      ),
    );
  }
}

Composition over inheritance. Instead of subclassing to tweak behavior, you nest widgets. Column inside Padding inside Center -- each widget does one job, and you combine them freely.

Widget Role
TextDisplays a string of text
IconRenders a Material icon glyph
ImageShows an image from network or assets
ContainerPaints, pads, and constrains a child
CenterCenters its child within the parent

03

Layout & Styling

Layout widgets don't paint anything themselves -- they arrange their children. Row and Column place children along an axis, Expanded fills leftover space, and Container handles decoration, padding, and sizing. Styling lives in widget properties and the app-wide ThemeData.

Key layout widgets

  • Row -- children side by side, left to right
  • Column -- children stacked top to bottom
  • Expanded / Flexible -- take a share of the remaining space
  • Stack -- children layered on top of each other
  • Padding / Center -- add space or center a child
Dart 
class StatsRow extends StatelessWidget {
  const StatsRow({super.key});

  @override
  Widget build(BuildContext context) {
    return Container(
      margin: const EdgeInsets.symmetric(horizontal: 16.0),
      padding: const EdgeInsets.all(12.0),
      decoration: BoxDecoration(
        color: Colors.blueGrey[50],
        borderRadius: BorderRadius.circular(8.0),
      ),
      child: const Row(
        mainAxisAlignment: MainAxisAlignment.spaceAround,
        children: [
          Expanded(child: _Stat(label: 'Followers', value: '12k')),
          Expanded(child: _Stat(label: 'Following', value: '340')),
          Expanded(child: _Stat(label: 'Posts', value: '58')),
        ],
      ),
    );
  }
}

class _Stat extends StatelessWidget {
  const _Stat({required this.label, required this.value});

  final String label;
  final String value;

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Text(value, style: const TextStyle(fontWeight: FontWeight.bold)),
        Text(label),
      ],
    );
  }
}
Widget Axis Use Case
RowHorizontalToolbars, stat rows, button groups
ColumnVerticalForms, cards, stacked content
StackNone (layered)Overlays, badges, backgrounds
ExpandedParent's axisSplit space evenly across children
Center--Center content on screen

Spacing tip: use SizedBox(width: 8) or SizedBox(height: 8) for small gaps, and Padding / EdgeInsets around groups. Reserve Container margins for spacing between widgets.

State & Interaction

A StatelessWidget renders the same UI forever. When data changes over time -- a counter, a text field, a checkbox -- you need a StatefulWidget. It keeps a separate State object, and calling setState() tells Flutter to rebuild that part of the tree.

How state works

  • StatefulWidget + createState() pair hold mutable data
  • setState(() { ... }) marks the widget dirty and schedules a rebuild
  • Buttons trigger callbacks: onPressed, onChanged, onTap
  • Hot Reload keeps state while updating code -- perfect for tweaking UI live
Dart 
class CounterPage extends StatefulWidget {
  const CounterPage({super.key});

  @override
  State<CounterPage> createState() => _CounterPageState();
}

class _CounterPageState extends State<CounterPage> {
  int _count = 0;

  void _increment() {
    setState(() {
      _count++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Counter')),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            Text('You pushed the button this many times:'),
            Text('$_count', style: Theme.of(context).textTheme.headlineMedium),
          ],
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _increment,
        child: const Icon(Icons.add),
      ),
    );
  }
}

setState is minimal. Only update values that affect the UI. Flutter rebuilds just the widgets that depend on changed data, so keep state local to the widget that owns it -- don't lift it up until you must.

Navigation & Lists

Apps have more than one screen. Flutter manages a navigation stack: Navigator.push() puts a new screen on top, Navigator.pop() removes it. For scrolling content, ListView builds items on demand -- the foundation of feeds and settings pages.

Navigation essentials

  • MaterialPageRoute -- the standard animated screen transition
  • Navigator.push(context, route) -- go forward, pass data in the constructor
  • Navigator.pop(context) -- go back, optionally returning a result
  • ListView.builder -- lazily builds only the visible list items
Dart 
class HomePage extends StatelessWidget {
  const HomePage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Topics')),
      body: ListView.builder(
        itemCount: topics.length,
        itemBuilder: (context, index) {
          final topic = topics[index];
          return ListTile(
            leading: const Icon(Icons.article_outlined),
            title: Text(topic),
            trailing: const Icon(Icons.chevron_right),
            onTap: () {
              Navigator.push(
                context,
                MaterialPageRoute(
                  builder: (context) => TopicPage(title: topic),
                ),
              );
            },
          );
        },
      ),
    );
  }
}

class TopicPage extends StatelessWidget {
  const TopicPage({super.key, required this.title});

  final String title;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(title)),
      body: Center(child: Text('You are viewing $title')),
    );
  }
}

const topics = ['Widgets', 'Layout', 'State', 'Navigation'];

Pass data forward, return results back. Construct the next screen with the data it needs, and use Navigator.pop(context, result) to hand a value to the previous screen -- for example, the selected item.

Your First App & Next Steps

Let's combine everything: state, layout, and interaction -- in one small task tracker. It uses a StatefulWidget to hold a list, renders it with ListView.builder, and adds new items with a text field.

Dart 
import 'package:flutter/material.dart';

void main() {
  runApp(const MaterialApp(home: TodoPage()));
}

class TodoPage extends StatefulWidget {
  const TodoPage({super.key});

  @override
  State<TodoPage> createState() => _TodoPageState();
}

class _TodoPageState extends State<TodoPage> {
  final _controller = TextEditingController();
  final List<String> _todos = [];

  void _addTodo() {
    final text = _controller.text.trim();
    if (text.isEmpty) return;
    setState(() => _todos.add(text));
    _controller.clear();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('My Tasks')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(12.0),
            child: Row(
              children: [
                Expanded(
                  child: TextField(
                    controller: _controller,
                    decoration: const InputDecoration(
                      hintText: 'Add a task...',
                      border: OutlineInputBorder(),
                    ),
                  ),
                ),
                const SizedBox(width: 8),
                IconButton.filled(
                  onPressed: _addTodo,
                  icon: const Icon(Icons.add),
                ),
              ],
            ),
          ),
          Expanded(
            child: _todos.isEmpty
                ? const Center(child: Text('No tasks yet. Add one above!'))
                : ListView.builder(
                    itemCount: _todos.length,
                    itemBuilder: (context, index) =>
                        ListTile(leading: const Icon(Icons.check_circle_outline), title: Text(_todos[index])),
                  ),
          ),
        ],
      ),
    );
  }
}

Flutter Fundamentals Quiz
Q1. What does Flutter compile your Dart code into for production apps?
Flutter compiles Dart ahead-of-time (AOT) to native machine code, which is why apps start fast and perform well on device. JavaScript and HTML come into play only for the web target.
Q2. In Flutter, everything you see on screen is built from...
The core Flutter idea: everything is a widget. Text, layout, and even the whole app are widgets composed into a widget tree.
Q3. Which widget arranges its children side by side, left to right?
Row lays children out horizontally; Column is vertical, and Stack layers them.
Q4. Which method tells Flutter to rebuild a StatefulWidget's UI?
setState() marks the widget dirty, scheduling a rebuild with the updated state. initState() runs once before the first build.
Q5. What is the correct way to navigate to a new screen in Flutter?
Screens are pushed onto a stack: Navigator.push(context, MaterialPageRoute(builder: ...)). Navigator.pop(context) goes back.
