01

Swift Fundamentals

Swift is a type-safe, compiled language introduced by Apple in 2014. Every value has a type the compiler knows, which catches entire classes of bugs before your code runs. The two keywords you will use most are let for constants and var for variables.

let vs var

  • let — declares a constant. Its value can never change once set. Prefer this by default.
  • var — declares a variable. Its value can be reassigned at any time.
  • Swift uses type inference — you rarely need to write the type explicitly.
Swift 
// Constants with let -- value cannot change
let appName = "Algo Infinity"
let maxRetries = 3

// Variables with var -- value can change
var score = 100
score += 50

// Type inference
var lives = 3
var health = 99.5
var isAlive = true
var player = "Alice"

// Explicit type annotations
var level: Int = 7
var greeting: String = "Hello"

// String interpolation
let message = "\(player) has \(lives) lives left"

// Collections
var scores: [Int] = [98, 87, 92]
var lookup: [String: Int] = ["Alice": 98]

// Control flow
if score >= 150 {
    print("New high score!")
} else {
    print("Keep going...")
}

for i in 1...3 {
    print("Attempt \(i)")
}

// Functions
func greet(name: String) -> String {
    return "Welcome, \(name)!"
}

Prefer let by default. Immutability makes your code easier to reason about and safe to share across threads. Only reach for var when a value genuinely needs to change.

02

Optionals & Safety

Swift's signature feature is optional safety. An optional is a type that may hold a value or be nil. The compiler forces you to handle the nil case, which eliminates the "null pointer" crashes that plague other languages.

Declaring & Unwrapping Optionals

  • Declare with a ? suffix: String? — the value may be absent
  • if let — safely bind the value to a new constant
  • guard let — early exit when the value is nil
  • ?? (nil coalescing) — provide a default value
  • ? optional chaining — short-circuit a whole chain
  • ! force unwrap — crashes if nil; use sparingly
Swift 
// Declaring an optional
var username: String? = "alice"
username = nil

// Optional binding with if let
if let name = username {
    print("Hello, \(name)")
} else {
    print("No username")
}

// guard let -- early exit
func validate(_ name: String?) {
    guard let safeName = name else {
        print("Name is missing")
        return
    }
    print("Valid: \(safeName)")
}

// Nil coalescing with ??
let displayName = username ?? "Guest"

// Optional chaining
let length = username?.count ?? 0

// Force unwrap -- use with care
// let forced = username!  // crashes if nil

Never force-unwrap unless you are certain. A force unwrap (!) on nil crashes your app. Prefer if let, guard let, and ?? — they are just as fast and impossible to crash.

Practice: Optionals

Given var email: String? = nil, what is the value of email ?? "no-email@example.com"?

  1. nil
  2. no-email@example.com
  3. Compile error
  4. A crash

Correct Answer: B

The nil coalescing operator ?? returns the right-hand side whenever the optional is nil. Since email is nil, the result is the fallback string.

03

Protocols & Extensions

Swift is a protocol-oriented language. A protocol is a blueprint of requirements — properties and methods — that conforming types must provide. Combined with extensions, protocols let you share behavior without inheritance hierarchies.

Protocol Fundamentals

  • Declare with the protocol keyword — a list of requirements
  • Conform with struct Car: Vehicle — multiple protocols separated by commas
  • Protocols can inherit other protocols
  • extension adds methods and properties to any type — even existing ones
  • Extensions can provide default implementations of protocol requirements
Swift 
// Defining a protocol
protocol Vehicle {
    var speed: Int { get }
    func start()
}

// Conforming to a protocol
struct Car: Vehicle {
    var speed: Int = 120
    func start() {
        print("Engine on")
    }
}

// Protocol inheritance
protocol ElectricVehicle: Vehicle {
    func charge()
}

struct Tesla: ElectricVehicle {
    var speed: Int = 200
    func start() { print("Silent power") }
    func charge() { print("Charging...") }
}

// Extensions add behavior to existing types
extension Int {
    var squared: Int { return self * self }
    func isEven() -> Bool { return self % 2 == 0 }
}

// Default protocol implementation
extension Vehicle {
    func describe() -> String {
        return "Moving at \(speed) km/h"
    }
}

Protocol-oriented programming (POP) prefers composition over inheritance: structs + protocols + extensions give you code reuse without the fragility of deep class hierarchies. This is the Swift community's recommended default.

Practice: Protocols & Extensions

Write a protocol Named with a requirement var name: String { get }, then write an extension that provides a default method greeting() returning "Hi, I am \(name)".

Swift 
protocol Named {
    var name: String { get }
}

extension Named {
    func greeting() -> String {

    }

    var name: String
}

print(alice.greeting())  // Hi, I am Alice
04

Closures & Higher-Order Functions

A closure is a self-contained block of functionality that captures and stores references to the constants and variables from its surrounding context. Closures are Swift's version of lambdas — and they power the standard library's higher-order functions.

Closure Essentials

  • Full syntax: { (a: Int, b: Int) -> Int in a + b }
  • Shorthand argument names: $0, $1 replace explicit parameters
  • Trailing closure syntax drops the parentheses when a closure is the last argument
  • @escaping marks closures that outlive the function call (e.g. stored callbacks)
  • Higher-order functions: map, filter, reduce, sorted
Swift 
// Closure syntax
let add: (Int, Int) -> Int = { (a, b) in
    return a + b
}

// Shorthand arguments
let multiply: (Int, Int) -> Int = { $0 * $1 }

// Capturing values
func makeCounter() -> () -> Int {
    var count = 0
    return {
        count += 1
        return count
    }
}

// Higher-order functions
let numbers = [3, 1, 4, 1, 5]
let doubled = numbers.map { $0 * 2 }
let evens = numbers.filter { $0 % 2 == 0 }
let sum = numbers.reduce(0) { $0 + $1 }

// Trailing closure syntax
let sorted = numbers.sorted { $0 < $1 }

// Escaping closure
func fetchData(completion: @escaping (String) -> Void) {
    DispatchQueue.global().async {
        completion("Data loaded")
    }
}
Function Purpose Example
mapTransform every element[1,2].map { $0 * 2 } → [2,4]
filterKeep matching elements[1,2,3].filter { $0 > 1 } → [2,3]
reduceCombine into one value[1,2,3].reduce(0) { $0 + $1 } → 6
sortedOrder elements[3,1].sorted { $0 < $1 } → [1,3]
forEachRun for each element[1,2].forEach { print($0) }

Closures capture by reference. The makeCounter example above keeps its own count alive after the function returns — that is Swift's closure capturing in action.

Practice: Closures

Using [1, 2, 3, 4, 5], write a single expression that filters even numbers and returns their squares, e.g. [4, 16].

Swift 
let result = [1, 2, 3, 4, 5]
    .filter { $0 % 2 == 0 }
    .map { $0 * $0 }
// result == [4, 16]

Memory Management & ARC

Swift manages memory automatically with Automatic Reference Counting (ARC). Every reference to a class instance keeps a count; when the count reaches zero, the instance is deallocated. The two things you must understand: value types vs reference types and retain cycles.

Value vs Reference Types

  • Value types (struct, enum) — copied on assignment; no ARC involved
  • Reference types (class) — share one instance; ARC tracks references
  • weak references don't increase the retain count — they become nil automatically
  • unowned references don't increase the count and assume the object lives forever
Swift 
class Person {
    var name: String
    var pet: Pet?
    init(name: String) { self.name = name }
    deinit { print("\(name) deallocated") }
}

class Pet {
    var name: String
    weak var owner: Person?   // weak breaks the cycle
    init(name: String) { self.name = name }
    deinit { print("\(name) deallocated") }
}

var alice: Person? = Person(name: "Alice")
var rex: Pet? = Pet(name: "Rex")
alice?.pet = rex
rex?.owner = alice

// Break the strong references
alice = nil
rex = nil
// Both deallocated -- no retain cycle

// Capture lists prevent retain cycles in closures
class DataLoader {
    func load(completion: @escaping () -> Void) {
        DispatchQueue.global().async { [weak self] in
            guard let self else { return }
            self.doWork()
        }
    }
    func doWork() { print("Working") }
}
Attribute Strong Weak Unowned
Increases retain countYesNoNo
Becomes nil automaticallyNoYesNo
Must be optionalNoYesNo
Typical useOwnershipParent-child backrefsGuaranteed lifetime

Retain cycle = memory leak. If A holds B strongly and B holds A strongly, neither is ever deallocated. Fix with weak on one side (or [weak self] / [unowned self] inside closures).

Practice: Memory & ARC

Two class instances reference each other with strong properties. When both external variables are set to nil, what happens?

  1. Both deallocate immediately
  2. Neither deallocates — a retain cycle leaks them
  3. Only the first deallocates
  4. The app crashes

Correct Answer: B

Two strong references that point at each other form a retain cycle. ARC can never drop the count to zero, so both objects leak. Declare one property weak to break the cycle.

iOS Ecosystem Basics

Swift is the language of the Apple platform. Understanding the iOS ecosystem means knowing the two UI frameworks, the app lifecycle, and modern async/await concurrency.

The iOS Toolkit

  • SwiftUI — Apple's modern declarative UI framework (iOS 13+)
  • UIKit — the classic imperative framework, still used in production apps
  • App lifecycle — @main entry point, scenes, and the run loop
  • async/await — structured concurrency replacing callbacks and delegate spaghetti
  • Swift Package Manager — dependency management built into Xcode
Swift 
// SwiftUI app entry point
import SwiftUI

@main
struct AlgoApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

// A SwiftUI view -- declarative UI
struct ContentView: View {
    var body: some View {
        Text("Hello, Algo Infinity")
            .padding()
    }
}

// UIKit equivalent -- imperative UI
import UIKit

class ViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        view.backgroundColor = .systemBackground
    }
}

// Async/await concurrency
func fetchProblems() async throws -> [String] {
    let url = URL(string: "https://api.example.com/problems")!
    let (data, _) = try await URLSession.shared.data(from: url)
    return try JSONDecoder().decode([String].self, from: data)
}

Task {
    let problems = try await fetchProblems()
    print(problems)
}

Error Handling & Result

Swift handles errors explicitly. A function that can fail declares throws, and callers must handle the error with do-catch, try?, or try!. This makes error paths visible and prevents silent failures.

Error Handling Tools

  • throws — marks a function that can fail
  • do-catch — runs risky code and handles errors
  • try? — convert the result into an optional (nil on failure)
  • try! — force unwrap the result (crashes on failure — use sparingly)
  • defer — run cleanup code when the scope exits, even on error
  • Result — represent success or failure as a value
Swift 
// Define a custom error type
enum FileError: Error {
    case notFound
    case permissionDenied
}

// A function that can throw
func readFile(named name: String) throws -> String {
    if name.isEmpty {
        throw FileError.notFound
    }
    return "Contents of \(name)"
}

// do-catch
func loadConfig() {
    do {
        let data = try readFile(named: "config.txt")
        print(data)
    } catch FileError.notFound {
        print("Config file missing")
    } catch {
        print("Other error: \(error)")
    }
}

// try? -- optional result
let maybeData = try? readFile(named: "config.txt")

// defer -- cleanup runs at scope exit
func processFile() throws {
    defer { print("Closing file") }
    let data = try readFile(named: "data.txt")
    print(data)
}

// Result type
func fetchUser(id: Int) -> Result<String, Error> {
    guard id > 0 else { return .failure(FileError.notFound) }
    return .success("User \(id)")
}

let result = fetchUser(id: 42)
switch result {
case .success(let name): print(name)
case .failure(let error): print(error)
}
Strategy Syntax Use Case
do-catchtry f() in a do blockHandle errors inline
try?let x = try? f()Treat failure as nil
try!let x = try! f()Failure is impossible
ResultResult<T, Error>Return success/failure as a value

Prefer do-catch and try?. try! crashes the program if the call throws — only use it when you are certain the operation cannot fail (e.g., reading a bundled resource).

Practice: Error Handling

Define an enum NetworkError: Error with a case invalidURL. Write a function fetch(from urlString: String) throws -> Data that throws NetworkError.invalidURL when the string does not start with "https://".

Swift 
enum NetworkError: Error {
    case invalidURL
}

func fetch(from urlString: String) throws -> Data {
    guard urlString.hasPrefix("https://") else {
        throw NetworkError.invalidURL

    return Data(urlString.utf8)
}

// Usage

    let data = try fetch(from: "https://api.example.com")
    print(data)
} catch {
    print("Request failed")
}

Generics & Advanced Types

Generics let you write flexible, reusable code that works with any type while keeping full type safety. Instead of repeating logic for each type, you write it once with a type placeholder — and the compiler checks correctness for every concrete type at compile time.

Generic Fundamentals

  • Type parameters use angle brackets: <T>, <Element>
  • Generic functions — func swap<T>(_ a: inout T, _ b: inout T)
  • Generic types — struct Stack<Element>
  • Type constraints — T: Equatable limits what T can be
  • Associated types — protocols declare placeholder types
  • some — opaque return types (Swift 5.1+)
Swift 
// Generic function
func firstElement<T>(of array: [T]) -> T? {
    return array.first
}

// Multiple type parameters
func makePair<A, B>(_ a: A, _ b: B) -> (A, B) {
    return (a, b)
}

// Generic type
struct Stack<Element> {
    private var items: [Element] = []
    mutating func push(_ item: Element) { items.append(item) }
    mutating func pop() -> Element? { return items.popLast() }
}

// Type constraint
func areEqual<T: Equatable>(_ a: T, _ b: T) -> Bool {
    return a == b
}

// Associated types in protocols
protocol Container {
    associatedtype Item
    var count: Int { get }
    mutating func append(_ item: Item)
}

extension Stack: Container {
    var count: Int { return items.count }
    mutating func append(_ item: Element) { push(item) }
}

// Opaque return type (SwiftUI)
import SwiftUI
func makeView() -> some View {
    return Text("Hello")
}
Concept Example Use Case

Generics vs Any: Any erases type information and needs runtime casts. Generics preserve the exact type — you get compile-time safety, autocompletion, and zero runtime cost.
