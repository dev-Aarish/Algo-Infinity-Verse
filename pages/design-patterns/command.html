Command

Turn a request into a stand-alone object that contains all information about the request, enabling parameterization, queuing, logging, and undo.

Intent

The Command pattern encapsulates a request as an object, letting you parameterize clients with different requests, queue or log requests, and support undoable operations. It turns a method call into a stand-alone object that contains everything needed to execute the call.

Problem

Direct method invocation couples the sender of a request to the receiver. This makes it impossible to queue requests, log them, schedule them for later execution, or undo them. For example, a UI toolbar that calls methods directly on application objects cannot easily implement undo/redo, macro recording, or task scheduling without significant coupling and duplication.

Solution

Define a command interface with a single execute() method. Concrete command classes wrap a receiver and the parameters needed to perform an action. The invoker (e.g., a toolbar button or queue processor) works only with the command interface and knows nothing about the receiver. For undo support, add an undo() method to the command interface.

Code Example — JavaScript

class Light {
  on() { console.log('Light ON'); }
  off() { console.log('Light OFF'); }
}

class LightOnCommand {
  constructor(light) { this.light = light; }
  execute() { this.light.on(); }
  undo() { this.light.off(); }
}

class LightOffCommand {
  constructor(light) { this.light = light; }
  execute() { this.light.off(); }
  undo() { this.light.on(); }
}

class RemoteControl {
  constructor() { this.history = []; }
  submit(command) {
    command.execute();
    this.history.push(command);
  }
  undo() {
    const cmd = this.history.pop();
    if (cmd) cmd.undo();
  }
}

const light = new Light();
const remote = new RemoteControl();

remote.submit(new LightOnCommand(light));  // "Light ON"
remote.submit(new LightOffCommand(light)); // "Light OFF"
remote.undo();                             // "Light ON"

Real-World Use Cases

  • Undo/Redo Systems — Text editors, image editors, and IDEs use command history for undo.
  • Task Queues & Job Scheduling — Encapsulate work units for delayed or distributed execution.
  • GUI Button Actions — Each toolbar or menu item holds a command object.
  • Macro Recording — Record a sequence of commands and replay them later.
  • Transactional Systems — Commands can be committed or rolled back as a unit.
