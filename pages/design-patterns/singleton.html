Singleton

Ensure a class has only one instance and provide a global point of access to it.

Intent

The Singleton pattern ensures that a class has exactly one instance throughout the application's lifetime and provides a global access point to that instance. It is one of the simplest yet most controversial design patterns, useful when exactly one object is needed to coordinate actions across the system.

Problem

Many real-world scenarios require a single, shared resource. A database connection pool, a configuration manager, a logging service, or a thread pool should not have multiple instances competing with each other. Without Singleton, you risk creating multiple instances that consume unnecessary memory, cause inconsistent state, or open redundant connections. The pattern also solves the problem of passing around a commonly needed object through every constructor and function.

Solution

The Singleton pattern hides its constructor so external code cannot call new directly. Instead, it exposes a static getInstance() method that returns the single instance. The first call creates the instance; subsequent calls return the cached one. This gives you controlled, lazy initialization and a guaranteed single point of access.

Structure

┌─────────────────────────────┐ │ Singleton │ ├─────────────────────────────┤ │ - instance: Singleton │ ├─────────────────────────────┤ │ - Singleton() │ │ + getInstance(): Singleton │ │ + businessMethod() │ └─────────────────────────────┘

Code Example — JavaScript

class ConfigManager {
  static #instance = null;

  #config = {
    apiUrl: 'https://api.example.com',
    timeout: 5000,
    retries: 3,
  };

  constructor() {
    if (ConfigManager.#instance) {
      throw new Error('Use ConfigManager.getInstance()');
    }
  }

  static getInstance() {
    if (!ConfigManager.#instance) {
      ConfigManager.#instance = new ConfigManager();
    }
    return ConfigManager.#instance;
  }

  get(key) {
    return this.#config[key];
  }

  set(key, value) {
    this.#config[key] = value;
  }
}

const config = ConfigManager.getInstance();
console.log(config.get('apiUrl')); // "https://api.example.com"

Real-World Use Cases

  • Configuration Managers — Load and serve app-wide settings from a single source.
  • Logging Services — Ensure all modules write to the same log file or sink.
  • Database Connection Pools — Reuse a fixed set of connections instead of opening new ones.
  • Thread Pools — Coordinate worker threads through a single pool manager.
  • Cache Stores — Maintain a single in-memory cache shared across the application.
